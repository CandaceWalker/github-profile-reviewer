# Reading a GitHub Profile: A Recruiter's Guide 🔎

You don't need to read code to get real signal from a GitHub profile. Here's what to look at, what to ignore, and what to ask.

## Strong signals
| Look for | Why it matters |
|---|---|
| **Pinned repos that match the role** | The candidate chose these to represent themselves |
| **A clear README** with what the project does and how to run it | Shows they think about other people using their work |
| **Tests** (folders or files named `test`, `tests`, or `spec`) | Shows professional engineering habits |
| **CI badges or a `.github/workflows` folder** | Automated checks run on their code, a sign of mature practices |
| **Merged pull requests to other people's projects** | Their code passed someone else's review |
| **Thoughtful commit messages** ("Fix race condition in order queue," not "stuff") | Shows clear communication |
| **Projects with history** (many commits over time) | Real projects evolve; tutorials are usually finished in a day |

## Weak or misleading signals
| Signal | Why to be careful |
|---|---|
| **Stars and followers** | Popularity, not skill |
| **The green contribution graph** | Easy to inflate, and it misses private work |
| **Forks** | Often a copy of someone else's project with no changes |
| **Tutorial or course repos** | Learning exercises, not original work |
| **Lots of tiny repos** | Can mean experimentation, not depth |

## The most important rule
**An empty GitHub is not a red flag.** Most professional engineers write code for their employer in private repos that no one outside the company can see. Many excellent senior engineers have almost nothing public. Use GitHub as a bonus signal, never as a requirement.

## Great screen questions from a GitHub profile
- "I saw [repo]. What problem were you solving, and why did you build it that way?"
- "What would you change about [repo] if you started it today?"
- "Tell me about your pull request to [project]. How was it received?"
- "Which of your public projects best represents how you work now?"

## Quick checklist (5 minutes per profile)
1. Open the pinned repos. Are any relevant to the role?
2. Open the most relevant one. Is there a README? Tests?
3. Check the commit history. Is it real work over time?
4. Look for pull requests to other projects.
5. Write down one question about a specific project for the screen.
