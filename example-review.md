# Example Review

A **fictional** example showing what the agent's output looks like. The candidate, repos, and projects below are made up.

**Role:** Senior Backend Engineer, Routing (Python or Go; optimization; production services)

---

**Candidate:** dev-jr42
**Public work available:** Some

**Relevant to this role**
- **`route-planner`** (Go): A delivery-route optimizer with about 200 commits over 14 months. Uses a published algorithm for vehicle routing and includes benchmarks comparing speed and route quality. Directly matches the "optimization" must-have.
- **`geo-tiles`** (Python): A small library for splitting map data into tiles. Relevant to the geospatial nice-to-have.
- **Pull request to a popular open-source routing project:** Added a performance fix that was reviewed and merged.

**Engineering habits seen**
- `route-planner` has tests, a CI workflow, and a README with setup steps and benchmark results.
- Commit messages are specific (for example, "Cache distance matrix to cut solve time 40%").

**Collaboration**
- One merged pull request to an external project, with constructive back-and-forth in the review comments.

**What GitHub doesn't tell us**
- Whether they've run a service in production at scale (a must-have). Their public projects are libraries and tools, not live services. This may be private work at their current employer.
- No visible mentoring or team leadership. That needs to come from the conversation.

**Questions for the screen**
- "In `route-planner`, how did you decide between speed and route quality?"
- "Tell me about the performance fix you contributed to [project]. How did you find the bottleneck?"
- "Have you run a routing or scheduling system in production? What broke, and how did you handle it?"
- "Which of your projects best reflects the work you'd want to do here?"

**Summary for the hiring manager**
Public work shows strong, relevant optimization experience in Go, with good engineering habits and a merged open-source contribution. Their experience running production services at scale and mentoring others isn't visible on GitHub and should be explored in the screen.
